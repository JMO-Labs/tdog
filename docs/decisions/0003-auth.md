# ADR-0003: Authentication providers

Status: proposed · 2026-11-13

## Context
tdog grants shell access to the host, so it's a high-value target. It runs behind Styx Portal
(author's setup) or standalone (public users), and may be internet-exposed.

## Decision
Pluggable provider, one active:
- `styx`: verify Styx-signed token (shared secret or JWKS) on every request and WS upgrade.
  Never trust proxy headers alone.
- `standalone`: Argon2id password; TOTP + recovery codes optional but strongly suggested
  (persistent banner when off-localhost without TOTP); optional passkeys; first-run setup token in
  logs; Secure/HttpOnly/SameSite=Strict cookie, 12 h idle; progressive lockout; logout-all;
  audit log.

Common: WS Origin check, CSRF on REST, only login + health unauthenticated.

## Consequences
Direct port exposure doesn't bypass auth. TOTP optional, so the UI nudge must stay visible.
